# Applying the updated AXON project to GitHub

This ZIP is a **source candidate**, not a proven APK. Keep a backup/restore tag before applying it. The current project still carries the complete original English dictionary and licence notices.

1. In the current GitHub repository, save a restore point. Upload the updated source ZIP to the repository root **if the automatic unpack workflow is not installed yet**. If it is already installed, upload into `uploads/` to avoid triggering an automatic full-project replacement while changing protected foundation files. Use **Actions → Unpack a zip into the repository → Run workflow**, with `zip_file` set to the exact uploaded ZIP path (for example `uploads/AXON-project.zip`) and `target_dir` set to `.`. The existing manual unpack workflow skips `.github/workflows/` as required by GitHub permissions. If your repository has no manual unpack workflow, create it first from `.github/workflows/unpack.yml`.
2. On GitHub's file editor, **manually replace** `.github/workflows/android-debug.yml` and **manually add** `.github/workflows/auto-unpack.yml` using the versions in this ZIP. They cannot be installed by an automatic-token unpack.
3. For repeatable Android updates, set **Settings → Secrets and variables → Actions → New repository secret** with name `AXON_DEBUG_KEYSTORE_B64` and the entire contents of the separately delivered private signing-key base64 file. Do **not** commit the keystore or the base64 text to a public repository. Without the secret, a build can still succeed, but its debug key is ephemeral and updates may require uninstalling.
4. Start **Actions → Android Debug APK → Run workflow**. Check the guard, Node/npm/memory line, snapshot check, foundation tests, generated package-lock and APK Release. This is the first true cloud proof. If anything fails, send the **first failing step** and its full log, not just the green/red summary.
5. For A4, upload a small ZIP containing `docs/auto-unpack-test.txt` to the repository root. The new automatic workflow should unpack it, remove the uploaded ZIP, run the strict guard, commit and dispatch an Android build. Verify the result on Actions; this is **not yet tested on GitHub**.
6. Install two consecutive signed APKs without uninstalling between them; check that a chat or taught meaning survives. In Settings, inspect Credits and check the dictionary. Export from both the AI Studio preview and the installed app, then compare each ZIP to the repository with `node tools/compare-dirs.mjs REPO_DIR EXPORTED.zip`. **Do not trust the new export as a project source until both comparisons show missing 0, extra 0, different 0.**
7. After these proofs, run G4 push experiments on throwaway repositories. Do not push the full real project directly from AI Studio into a new production repository yet.

**Caution:** the generated source snapshot (`public/_axon-source/`) is ignored by Git and rebuilt before Vite. The packed dictionary converter is only a candidate; it does not replace or delete production data.
